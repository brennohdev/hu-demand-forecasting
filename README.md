# hu-demand-forecasting

Forecasting **antimicrobial demand** for the pharmacy of the *Hospital Universitário
Lauro Wanderley* (HU-UFPB). Course project for **Supervised Machine Learning
(MLS 2026.2)** — UFPB/CCSA, *Ciência de Dados para Negócios*.

**Team F:** Brenno Henrique Alves da Silva Costa · Gustavo Henrique Rocha Oliveira ·
Iasmin Vieira de Lima.

---

## Where this came from

The project started around drug shortage in the public health system (SUS). During a
stakeholder interview at the HU-UFPB pharmacy, the person in charge told us that general
shortage is largely under control and pointed to the real pain: **controlling
antimicrobials so that no patient's treatment is interrupted for lack of stock**. Today
this is tracked in a **manual spreadsheet**, one row per treatment (drug, sector, start,
end, daily and total quantity), reconciled against the AGHU stock position.

So the problem we actually model is: **estimate next month's demand for each
antimicrobial**, to support the pharmacy's reorder decision under a quarterly purchasing
cycle (CAF) and limited staff.

- **User / decision:** pharmacy team deciding how much of each antimicrobial to reserve/reorder.
- **Unit:** one treatment (aggregated to *active ingredient × month* for forecasting).
- **Target:** monthly demand (sum of planned quantity).
- **Horizon / cut:** forecast the next month, at month close (no future leakage).

## Data

Two workbooks received from the pharmacy (academic use only). **Raw data is not
versioned** — see [`data/raw/README.md`](data/raw/README.md) for how to place it.
The patient name already comes anonymized (empty) in the file we received, so the base
holds **no identifiable personal data**. The processed base is regenerated by the
pipeline/notebook.

Coverage: **7,261 treatments, 32 antimicrobials, 17 sectors, Mar/2025–Oct/2026**
(Oct/2026 is partial and excluded from modeling).

## Machine learning / data engineering practices applied

- **Layered pipeline** (`ingestion → processing → features → modeling`) as a proper
  Python package, not loose scripts.
- **Raw data preserved** and isolated from transformations; processed base is a
  reproducible output, never hand-edited.
- **Temporal train/test split** because the decision targets the future (no random split).
- **Leakage diagnosis**: target, temporal and decision-consequence leakage are classified
  explicitly (see [`docs/diagnostico_vazamento.md`](docs/diagnostico_vazamento.md)).
  Tempting columns like `situacao` and `qtd_dispensada` are **banned** because they only
  exist after the decision.
- **Honest baselines before any model**: a trivial (train mean) and an operational
  (persistence) baseline define the number every future model must beat.
- **Interpretable metric** (MAPE), chosen to match the pharmacy's reorder decision.
- **Reproducibility**: pinned dependencies, `uv.lock`, a `Makefile`, and a notebook that
  runs end to end with no absolute paths.

### Baseline (reference number of the semester)

Temporal split — train: 2025-03→2026-05, test: 2026-06→2026-09.

| baseline | MAPE | MAE |
|---|---|---|
| Trivial (train mean) | **9.6%** | 1,478 |
| Operational (persistence / reorder like last month) | 15.8% | 2,262 |

Demand is stable, so the mean is already a strong competitor: **any model must beat
~9.6% MAPE** to justify its complexity.

## Reproduce

Requires [`uv`](https://docs.astral.sh/uv/) and the raw workbooks placed in `data/raw/`.

```bash
make setup      # create the env and install the package (uv)
make notebook   # run the audit notebook end to end, saving outputs
# or, in the terminal:
make pipeline   # ingestion -> baseline, prints the baseline numbers
```

Without `make`:

```bash
uv sync --extra notebook
uv run jupyter nbconvert --to notebook --execute --inplace notebooks/auditoria_baseline.ipynb
```
